UI y UX: qué son y en qué se diferencian

Antes de escribir tu primera línea de HTML conviene tener claro qué estás construyendo: la interfaz (lo que se ve y se toca) y la experiencia (cómo se siente usarla). Son dos capas del mismo producto y las dos importan.

schedule~6 min de lectura schoolNivel introductorio arrow_forwardDespués: Principios de diseño

Dos capas del mismo producto

Cuando abres una app ves una sola cosa, pero en realidad hay dos trabajos distintos detrás. La UI (del inglés User Interface, «interfaz de usuario») es la capa visible. La UX (User Experience, «experiencia de usuario») es cómo de bien resuelve tu problema esa app. Puedes tener una sin la otra: hay apps feas que funcionan de maravilla y apps preciosas en las que te pierdes.

brush

Interfaz (UI): lo que se ve y se toca

Colores, tipografías, espacios, botones, iconos, imágenes. Es casi todo lo que vas a escribir cuando empieces a programar Frontend: la estructura con HTML y el aspecto con CSS.

  • check_circle Botones, formularios e iconos → HTML
  • check_circle Color, tipografía y espaciado → CSS
  • check_circle Cambios al pasar el ratón → CSS :hover, transition
psychology

Experiencia (UX): cómo se siente usarla

¿Encuentro rápido lo que busco? ¿Entiendo qué pasó al pulsar? ¿Tiene los pasos justos? Estas decisiones se toman antes de programar, dibujando esquemas y flujos de pantalla.

  • check_circle Entender qué necesita la persona usuaria
  • check_circle Ordenar la información: qué va primero y qué después
  • check_circle Diseñar el recorrido: pantalla A → pantalla B
lightbulb

Analogía: imagina que construyes una casa. La UX es el plano: cuántas habitaciones hay y por dónde se pasa. La UI es el acabado: el color de las paredes y los muebles. Una casa con muebles preciosos en la que hay que cruzar el baño para llegar a la cocina tiene buena UI y mala UX.

¿En qué orden ocurren en un proyecto?

Casi siempre primero se piensa la UX y luego se pinta la UI. Si programas el aspecto antes de tener claro el recorrido, acabas rehaciendo pantallas.

  1. 1
    Entender (UX)

    Se investiga qué necesita la persona y se define el problema a resolver.

  2. 2
    Estructurar (UX)

    Se dibujan esquemas simples (wireframes) y el flujo de pantallas, sin colores todavía.

  3. 3
    Vestir y construir (UI)

    Se elige color y tipografía, y se programa la interfaz con HTML y CSS.

Bonito no siempre significa usable

Esta pantalla de tienda tiene una UI cuidada, pero cuesta usarla. Toca cada problema para ver qué falla y cómo se soluciona. Casi todo se arregla con decisiones de UI concretas que aprenderás en las siguientes lecciones.
