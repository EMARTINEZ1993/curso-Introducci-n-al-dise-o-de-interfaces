Accesibilidad: que funcione para todo el mundo

Hay personas que no ven bien los colores, que navegan solo con el teclado o que usan un lector de pantalla. Una interfaz accesible sigue funcionando para ellas. Y casi todo se consigue escribiendo bien el HTML desde el principio.

Pautas WCAG (POUR)

Las WCAG son la guía estándar de accesibilidad web. Se resumen en cuatro ideas (POUR): el contenido debe poder percibirse, operarse, entenderse y ser robusto (funcionar en distintos navegadores y ayudas técnicas).

Perceptible

La información y los componentes de la interfaz de usuario deben presentarse a los usuarios en formas que puedan percibir (por ejemplo, alternativas de texto para imágenes).

Operable

Los componentes de la interfaz de usuario y la navegación deben ser operables (por ejemplo, accesibilidad del teclado, tiempo suficiente para leer).

Comprensible

La información y el funcionamiento de la interfaz de usuario deben ser comprensibles (por ejemplo, lenguaje claro, comportamiento predecible).

Robusto

El contenido debe ser lo suficientemente robusto como para que pueda ser interpretado de manera confiable por una amplia variedad de agentes de usuario, incluida la tecnología de asistencia.

Contexto del Lector de Pantalla

Un lector de pantalla lee la página en voz alta a partir del HTML, no de cómo se ve. Si usas la etiqueta correcta para cada cosa (<button>, <nav>, <h1>…), esa persona entiende la página sin verla.

Contraste de Color (AA / AAA)

WCAG requiere un contraste suficiente entre el texto y el fondo. El nivel AA requiere una relación de contraste de al menos 4.5:1 para texto normal y 3:1 para texto grande. El nivel AAA requiere 7:1 para texto normal y 4.5:1 para texto grande.

El color no lo es todo

Nunca use el color como el único medio para transmitir información, indicar una acción, solicitar una respuesta o distinguir un elemento visual.
